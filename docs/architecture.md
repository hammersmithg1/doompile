# Архитектура и работа через агента

Проект рассчитан на личную коллекцию и небольшой круг пользователей. Общий редактор работает в вебе, WKWebView и Web Clipper; навигация, клавиатура, Share Sheet и AppKit остаются платформенными. Слияние параллельных правок не автоматизируется: сервер проверяет ревизию, клиент сохраняет отдельную конфликтную копию.

## Источники общих правил

| Источник | Что менять здесь |
| --- | --- |
| `packages/contracts/protocol.json` | Версии API/документа, лимиты и команды редактора |
| `packages/contracts/telemetry.json` | События, разрешённые свойства и лимиты диагностики всех платформ |
| `packages/contracts/observability-coverage.json` | Сценарии и точки продуктового/технического покрытия |
| `packages/design/tokens.json` | Семантические цвета, размеры, радиусы и типографика |
| `packages/core` | Формат заметки и чистые функции |
| `packages/core/test-fixtures` | Одинаковые примеры поведения для TypeScript и Swift |
| `packages/editor` | Схема блоков, редактирование, команды и сохранение неизвестного содержимого |
| `apps/ios/Shared` | Общее нативное хранение, модели и синхронизация iOS/macOS/extensions |

После изменения JSON выполнить `npm run shared:generate`. Генерируемые CSS/TS/Swift входят в репозиторий; `npm run shared:check` обнаруживает расхождения. Это обычные файлы и скрипт Node, без отдельного сервиса или дополнительного инструмента сборки.

Изменение представления не должно менять формат заметки. Неизвестный блок показывается как «Ошибка отрисовки» и сохраняется в исходном виде при редактировании соседнего содержимого. Новые типы блоков должны проверяться через round-trip старым редактором. Переносить новые поля в HTML или восстанавливать данные из визуального представления нельзя.

`GET /api/capabilities` возвращает версию API, версию документа, лимиты и команды. Заголовок `X-Doompile-API-Version` позволяет серверу отклонить несовместимую версию до записи. Клиенты без заголовка поддерживаются как версия 1. Повышать версию нужно при несовместимом изменении контракта; добавление блока с безопасным fallback само по себе не требует сложных миграций.

## Хранение и синхронизация

Локальное сохранение и отправка серверу — разные операции. «Сохранено» в редакторе означает долговечное сохранение на устройстве; состояние очереди отображается отдельно. Ошибка одной заметки не должна останавливать остальные записи и получение изменений.

Веб хранит отдельные записи IndexedDB и мигрирует прежний ключ с полной коллекцией. Изменения между вкладками сообщаются через BroadcastChannel, отправка координируется между вкладками. Подтверждение старого запроса никогда не заменяет более свежий ввод.

Нативное хранилище использует SQLite и транзакции по отдельным заметкам. Старый `notes.json` импортируется при первом открытии; исходный файл сохраняется как резервная копия и не становится рабочей базой снова. App Group и межпроцессная координация остаются общими для приложения и extensions. Сохранение одной заметки не должно повторно сериализовать всю коллекцию. Share/Action отправляют только неотправленные записи и не загружают всю коллекцию в память расширения.

Загрузка файла повторяется с прежним UUID в `X-Doompile-Upload-ID`. Подтверждение загрузки фиксируется до сохранения заметки. Потеря ответа не должна создавать новый файл и ложную конфликтную копию. Без заголовка старый upload API продолжает работать.

Автосохранение отправляет только очередь. Полная коллекция загружается при открытии, возвращении, ручной синхронизации и периодической проверке; полный pull после каждого автосохранения не выполняется. Для тысяч небольших заметок сначала измеряется реальное время/объём; change cursor и пагинация добавляются при подтверждённой необходимости. Это отдельная оптимизация, она не требует менять UI или усложнять конфликты.

## Модули веб-интерфейса

Новые сценарии должны включать наблюдаемость и офлайн-диагностику по [общему контракту и процессу](observability.md). API используют `api`/`observedRoute`, а клиенты — общие границы сохранения и транспорта; проверки входят в `npm run verify`.

`doompile.tsx` координирует рабочую область. Быстрый ввод находится в `quick-composer.tsx`, настройки/авторизация/экспорт — в `settings-dialog.tsx`, поверхность редактора — в `note-editor-surface.tsx`. Подготовка документов и ключ сравнения содержимого находятся в `lib/client/editor-model.ts`; сохранение и очередь не зависят от React-компонентов.

## Проверки

```sh
npm ci
npm run verify           # генерация, типы, unit/API, infra, сборки
npx playwright install chromium webkit
npm run verify:ui        # редактор, mobile web, desktop/mobile clipper
npm run verify:native    # macOS/Xcode: Swift, Mac behavior, обе сборки
```

Веб-сборка проверки использует `.next-verify`, UI-тесты — отдельные порты и базы. Проверка клиппера собирает `.test-build`, не заменяя папку расширения, загруженную пользователем в Safari.

CI запускает веб/контракты, браузерные сценарии, iOS и macOS для одного commit. Автоматические deploy/TestFlight/подписанный Mac release зависят от всех четырёх проверок. Быстрые unit-тесты не заменяют платформенные smoke-сценарии клавиатуры, сохранения при закрытии, Share и Safari.

## Серверная разработка и релизы

Агент на Linux редактирует все исходники и запускает web/UI-проверки; Apple-сборки и симуляторы выполняет macOS CI. Секреты получают через setec, не записывают в checkout или клиентские `.env`. Изменения должны проходить проверки до обновления рабочих приложений. Настройка настоящего devbox, домена и Apple-аккаунта описана в `deployment.md`.

Перед включением автообновлений веба проверить backup и восстановление на отдельном экземпляре. `node infra/verify-backup.mjs /absolute/backup` проверяет SQLite и наличие/размер файлов, но не заменяет запуск восстановленного приложения.

Mac release-скрипт создаёт Developer ID-подписанный и notarized ZIP с `release.json` (commit, версия контракта, размер и SHA-256) и подписанным appcast. Sparkle в macOS-приложении проверяет канал/архив, загружает обновление и устанавливает его с перезапуском; заметки и черновики сохраняются через обычное завершение приложения. Публичный сервер хранит только готовые артефакты, закрытый Ed25519-ключ остаётся в setec. Публикация заменяет appcast атомарно после ZIP и не допускает отката версии. TestFlight использует штатную доставку Apple. Реальные Developer ID подпись, notarization и upgrade/relaunch проверяются после подключения Mac credentials и развёртывания канала; ad-hoc smoke-тест проверяет подписи, но не является такой проверкой.
